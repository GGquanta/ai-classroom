# Claude Opus 5.5 公开作品与实践盘点：强在哪、怎么用、何时换

## 六步速览

1. 先分清：Opus 5.5 **适合什么任务**，不适合什么任务
2. 按场景看公开作品：编码长跑、前端整页、代码拍视频、知识工作、多 Agent 协调
3. 抽出共用打法：事实清单 → 分步验收 → 力度（effort）按阶段调
4. 对照站内已有文章：动效深潜看「代码拍视频」；日常选模型看「常用模型怎么选」
5. 团队落地：定「默认用 / 慎用 / 换模型」三条规则，写进 Rules 或口头约定
6. 自检：有没有把「能炫」当成「该用」？成本与范围是否写清？

对应三原则：**先看作品类型 · 再抄可执行流程 · 最后按成本选型**。

> 说明：能力描述与价格以 Cursor / Anthropic 公开文档为准；公开作品与仓库会持续更新，文中案例作方法参考，不构成完整索引。界面与档位名称以你本地 Cursor 为准。

## 先建立心智模型：Opus 5.5 强在哪

综合公开文档与早期实践，Opus 5.5 相对前代更常被提到的点：

| 能力面 | 公开侧重点 | 对日常工作的含义 |
|--------|------------|------------------|
| 长任务 Agent | 多步编码、迁移、审计更稳 | 适合跨文件、跨小时的主路径任务 |
| 前端 / UI | 从零搭完整界面的口碑较好 | 适合整页/整模块实现，仍要设计约束 |
| 沟通 | 说明「做了什么、为什么」更克制 | 长对话更好跟，减少「写了一堆不知所云」 |
| 子代理协调 | 委派清晰、主任务不易跑偏 | 适合拆子任务并行（需 harness 配合） |
| 视觉材料 | 读图、读表、读流程图更准 | 适合截图纠偏、图表核对、流程框图续改 |
| 成本 | 仍是 Opus 档价，比轻量模型贵 | 简单改动不必默认上 Opus |

**硬习惯：**

- 简单 typo / 单行逻辑 → 不必上 Opus 5.5
- 规格含糊 → 先 Ask/Plan 定边界，再开高档模型
- 「能做出炫酷 demo」≠「业务该用这套流程」

## 公开作品怎么分类看

最近讨论多的 Opus 5.5 相关作品，大致可归五类。调研时按类收藏，比按标题刷更有用。

### 1. 仓库级编码与重构

**典型形态：** 多文件改动、补测试、迁移接口、长跑 Agent 直到 `build`/`test` 通过。

**可抄点：**

- 先写可勾选验收清单，再让模型动手
- 一步一验收，避免「一次做完整仓」
- 合并前用只读审查对照「明确不做」

**适合谁：** 研发、需要啃遗留代码的同学。

### 2. 前端整页 / 产品界面

**典型形态：** 从文案与布局约束生成可运行页面；或按截图纠偏到接近设计稿。

**可抄点：**

- 先定气质、参考站、明确不借鉴什么（见站内官网设计文）
- 要求 Design Token / 变量，而不是散落 hex
- 用截图 + 「只改视觉、不改数据层」收窄 diff

**适合谁：** 前端、产品原型、官网落地。

### 3. 代码拍视频 / 动效成片

**典型形态：** 不直接「生成 MP4」，而是写 HTML/Canvas/GSAP/Remotion/Manim，再逐帧截取合成。

**可抄点：** 事实清单、分镜、节拍表、抽帧自检——细节见站内专文，本文不重复展开。

**调研时怎么用这篇专文：** 先看「引擎选型表」，再挑一个与你任务匹配的案例仓库复现一条最短片。

### 4. 知识工作与材料生产

**典型形态：** 报表核对、幻灯/文档草稿、从长材料抽事实并写摘要；强调少编数字、少错引。

**可抄点：**

- 数字与结论必须带来源或标注「待核实」
- 先结构化大纲，再扩写
- 对外稿走「去 AI 味」检查（见站内相关文）

**适合谁：** 调研报告、宣讲材料、对内汇报。

### 5. 多 Agent / 子任务编排

**典型形态：** 主模型拆任务，子代理分别探索、实现、审查，主任务保持清单不丢项。

**可抄点：**

- 主对话只保留目标、约束、待办状态
- 子任务结束要回写「做了什么 / 验证了什么」
- 无人值守时：文本汇报 ≠ 任务完成，清单未清零就继续

## 从作品里抽出的共用打法

不同赛道的爆款演示，流程其实很像：

```
选对任务类型
  → 准备「事实 / 约束 / 验收」三件套
  → 选力度（effort）：草稿低、主路径中、精修高
  → 分步执行并留下可检查产物（diff、静帧、清单勾选）
  → 人做终审：事实、范围、成本
```

![Opus 5.5 调研到落地的共用闭环](images/opus55-survey-loop.png)

### 力度（effort）怎么跟作品类型对齐

公开实践与文档建议可简化为：

| 阶段 | 建议力度 | 说明 |
|------|----------|------|
| 分镜 / 大纲 / 方案对比 | 低～中 | 要快迭代，不要一次想完美 |
| 主路径实现 | 中（文档默认常够用） | 不必盲目抄上一代的 high |
| 逐帧精修 / 难 bug / 强审查 | 高 | 贵，只打在收口阶段 |
| 长时间无人值守 | 按 harness 文档调，并设停止条件 | 防止「汇报完就停」或无限续跑 |

> 注意：Effort 档位名在不同模型间**不可直接等价换算**。从 Opus 5 迁到 5.5 时，先按中档测，再上下调，不要原样沿用旧设置。

## 团队调研清单（可直接套）

做一个上午的调研，建议按这张表填，避免只收藏链接：

| 字段 | 写什么 |
|------|--------|
| 作品名 / 链接 | 仓库、演示页或帖子 |
| 类型 | 编码 / 前端 / 动效 / 知识工作 / 多 Agent |
| 输入是什么 | 文案、截图、数据、分镜… |
| 输出是什么 | 可运行代码、MP4、PPT、报告… |
| 可复制的 3 步 | 用自己的话写，不抄营销句 |
| 依赖工具 | Skill、渲染引擎、MCP… |
| 成本敏感点 | Token、人工校对、渲染时间 |
| 我们能不能用 | 能 / 需改造 / 暂不适用（写原因） |

填满 5～8 个样本后，再写一页「团队默认策略」比空谈模型强弱有用。

## 何时用 Opus 5.5，何时换模型

| 情况 | 建议 |
|------|------|
| 跨模块实现 + 要跑通测试 | 优先考虑 Opus 5.5（或团队认定的同级强模型） |
| 整页 UI、强约束下的视觉落地 | 可用；配合设计约束与截图验收 |
| 代码拍视频、复杂动效时间线 | 可用；流程跟专文，别只换模型名 |
| 单文件小改、生成 commit message | 换更轻量/更便宜的模型 |
| 只要检索问答、不改仓库 | Ask + 中小模型通常够用 |
| 必须本地/专有云、数据不出域 | 先看合规与 ZDR/部署约束，再谈模型名 |

## 常见踩坑

| 踩坑 | 后果 | 更好做法 |
|------|------|----------|
| 所有任务默认 Opus 5.5 | 费用陡增，简单活也被拖慢 | 按任务表分流 |
| 只追 demo，不写验收 | 好看不可维护、不可复现 | 每类作品留「最短可复现步骤」 |
| 把动效专文流程当成万能模板 | 编码任务被节拍表绑架 | 按作品类型选流程 |
| Effort 原样沿用 Opus 5 的 high | 更慢更贵，未必更好 | 从 medium 起测 |
| 长任务把「阶段汇报」当成结束 | Agent 停在半路 | 清单未清零就继续；设明确完成条件 |
| 对外材料不核对数字与出处 | 可信度事故 | 知识工作类强制「来源 / 待核实」 |

## 一分钟自检（调研或动手前）

- [ ] 这个任务属于五类作品里的哪一类？
- [ ] 有没有现成站内专文可直接跟（尤其是动效）？
- [ ] 事实、约束、验收三件套写了吗？
- [ ] 是否必须用 Opus 5.5？能否降档？
- [ ] 结束时留下的是可复现产物，还是只剩一段聊天？

## 附录：Prompt 模板

### 调研：给一批链接做分类摘要

```text
以下是与 Claude Opus 5.5 相关的公开作品/帖子链接或摘要：
【粘贴】

请按「编码 / 前端 / 动效 / 知识工作 / 多 Agent / 其他」分类。
每条输出：一句话做什么、输入、输出、可复制的 3 步、不适用场景。
不要夸大能力；不确定就标「待核实」。
```

### 落地：把某个 demo 收成团队最短复现

```text
作品说明：【粘贴】
我们环境：【Cursor / 是否可装 Skill / 网络限制】

请写出「30～60 分钟可复现」步骤：
1）准备什么材料
2）用什么模式与模型档位（含 effort 建议）
3）如何验收
4）失败时如何降级（换模型或缩小范围）
不要写营销句。
```

### 选型：这个任务要不要上 Opus 5.5

```text
任务：【一句话】
约束：【时间 / 预算 / 是否改仓库 / 是否对外】
已有材料：【有/无验收清单、设计稿、测试】

请建议：
1）是否使用 Opus 5.5（是/否/仅收口阶段用）
2）若否，用哪类更轻的模型或流程
3）开干前还缺什么信息
```

### 编码长跑：主路径任务卡

```text
目标：【主路径一句话】
明确不做：【列表】
验收：【可勾选条目】
约束：最小改动；每完成一步更新待办；未清零不要结束。
请先给出 Plan（文件清单与验证方式），确认后再逐步实现。
```

### 前端整页：防模板味

```text
页面：【名称】
参考气质：【1～2 个可公开参考，说明借鉴什么、不借鉴什么】
禁止：通用紫色渐变模板风、无意义大圆角卡片堆砌
交付：可运行页面 + 简短 Design Token 说明
先出 2 个互斥方向的静帧描述，我选一版再写代码。
```

### 知识工作：防幻觉

```text
材料：【粘贴或 @ 文件】
任务：【摘要 / 校对 / 提纲】
要求：
- 数字与专有名词必须能在材料中定位；不能则标「待核实」
- 先给结构，再写正文
- 不要编造未出现的结论
```
