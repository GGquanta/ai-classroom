# 对话开太久了：什么时候该新开窗口

和 AI 聊着聊着，质量会掉：刚才约好「只改这一页」，它却去动别的文件；开场让它用表格，后半段又改回大段散文；同一个报错纠正两遍，它仍按第一次猜的方向改。这经常不是模型突然变笨，而是**这条对话已经太满、太杂**。

模型一次能同时看住的内容有上限（常叫上下文窗口）。对话轮次、贴进去的材料、它自己读过的文件，都会占位子。位子一挤，早期约定会被挤到边上，失败过的猜法却还留着。官方和社区把这种现象叫「上下文腐烂」：窗口越大、越杂，注意力越散。

![对话窗口挤满后，早期约定被挤到边上](images/01-window-overflow.png)

日常最常用的是三条：**接着聊**、**压缩**、**新开窗口**。下面按能判断的信号写，不绑定某一个软件。网页里的聊天助手、编辑器里的助手，规则一样。

## 一事一窗

一条对话只干一件事。改完一页说明、修好一个报错、整理完一份纪要，下一件换窗口。

Anthropic 的公开建议也是这句：开始新任务，就开新会话。把十几个互不相关的问题串在同一条长链里，助手会同时背着旧目标、旧改动、旧的错误假设。压缩可以腾位子，但压缩是有损的，不能当「无限续聊」用。

同一件事的连续追问可以续。例如：还在查同一个报错，第二轮贴了更完整的日志。目标、范围、怎样算完成，这三样有一样变了，就新开。

## 续聊、压缩、新开：怎么选

![续聊、压缩、新开三选：换任务就拉开新窗口](images/02-three-choices.png)

| 情况 | 选哪条 | 原因 |
| --- | --- | --- |
| 还在做同一件事，质量正常 | 续聊 | 不用重讲背景 |
| 还在同一件事上，窗口快满，或回答开始丢细节 | 压缩 | 腾位子，把关键结论留下；细节会丢一些 |
| 换了任务、换了材料范围、换了「怎样算完成」 | 新开 | 旧对话里的目标会干扰新任务 |
| 同一件事纠正两次，仍按老路走 | 新开 | 窗口里堆满失败路径，再聊等于带着旧错往下走 |
| 忘了开场约定，或改了你明确不让动的地方 | 新开 | 多半已经「看不见」早期约束 |

压缩不是新开。还在同一条任务上、只是窗口快满，才压缩。任务已经换了，清空重来更干净。

各软件叫法不同，意思接近：

- **压缩**：把目前对话收成摘要再继续。占用提示偏高时，直接告诉助手按你指定的要点总结后再聊。Claude Code 里对应 `/compact`。可以加一句「重点保留已改材料和未完成项，丢掉试错过的弯路」。
- **新开**：新开一个对话窗口。Claude Code 里对应 `/clear`。不要把整段旧聊天粘进去。

有人会看输入框旁边的占用提示。社区经验是：别等它自己挤到 100%。大约七成到八成、又还在同一任务上，可以先手动压缩。提示没有、或你用的是网页聊天，就靠下面的现象判断。

## 该新开时，窗口里往往已经这样了

这些信号比「聊了多少轮」更准：

- 你写过的约束它不再遵守（例如「不要改数字」「只动这一段」）。
- 开始改无关材料，或把已经否决的方案再拿出来。
- 前后口径打架：同一名词两种用法，同一结论两套说法。
- 同一问题你纠正了两遍，它仍重复第一次的改法。
- 你已经换题了，它还在用上一题的文件名、人名、表格结构。

上面任意一条出现，就不要再往这条对话里加新任务。先收尾或先交接，再开新窗口。

## 新开前写一份短交接，不要贴全文

新窗口最怕两件事：什么背景都不给，只好再猜一遍；把整段聊天记录贴进去，等于把噪音原样搬过去。

![新窗口只收短交接，不要整段聊天](images/03-handoff-card.png)

让旧窗口先写一份很短的交接（大约 5～10 行），新窗口只贴这一段。可直接对旧窗口说：

```text
这条任务先停。不要继续改当前材料。

请用不超过 10 行写一份交接，只保留下一窗口用得上的信息：
- 目标（一句话）
- 已经改过 / 已经确认的结论
- 还没做完的
- 明确不要再做、不要再碰的
- 试过但无效的方向（各一行，避免下一窗口重走）

不要粘贴完整对话，不要写过程流水账。
```

新窗口第一句可以是：

```text
这是上一窗口的交接，按它继续，不要发明交接里没有的约束。

<把上面生成的 10 行贴在这里>

当前只要做：<这一件新任务或未完成的那一件>
范围：<只动哪些材料>
完成标准：<怎样算做完>
```

相关但不必带着全部历史的工作（例如刚改完正文，接着只想润色标题），也可以新开，把交接里的「已改材料 / 已定口径」带过去即可。不必为了省事把旧窗口无限续下去。

## 压缩时交代「留下什么」

还在同一件事、只是对话太长时，压缩比新开省事。压缩会丢细节，所以要写清留下什么。可直接说：

```text
请把目前对话收成摘要后继续，不要换任务。

摘要必须保留：
- 当前目标
- 已改过的材料名称
- 已否决的做法
- 未完成项

丢掉：试错过程、重复解释、已经过时的猜测。
```

压缩完先抽查一句开场约束（例如「还约定只改这一页吗？」）。答不上来，就不要再压，改为新开并贴交接。

## 日常怎么用

1. 开窗口时写清三样：要做什么、动哪些材料、怎样算完成。
2. 这一件做完，下一件换窗口。
3. 还在同一件、开始丢细节或占用提示偏高：压缩，并写明留下什么。
4. 换任务、纠正两次仍走老路、忘了开场约定：新开；先让旧窗口写 10 行交接。
5. 新窗口只贴交接，不贴全文。

项目里反复出现的规矩（文风、目录、禁止事项）适合写进给助手看的固定说明，例如项目根目录的 `AGENTS.md`，这样每个新窗口都带得上，不必靠一条超长对话来「记住」。写法可参考 [AI 编程工具快速指南](/articles/tools/ai-coding-tools-guide)。

## 小结

对话不是越长越懂你。一事一窗；换目标就换窗口；同一件事纠了两次就清掉重来。还在原任务上、只是窗口挤了，才压缩。新开前写短交接，比把聊天记录整段搬走更干净。窗口只是工作台，不是档案室。
