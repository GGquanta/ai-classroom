# 专项申报流程指南

把「通知原文 / 政策链接 → 可执行申报手册」做成短流程。  
**本 Skill 出「怎么报」；不替代申报书正文填报**（正文见 `gov-tech-shenbaoshu-docx` / 专用申报书 Skill）。

配图见 `images/`（工作流、落地路径、指南与申报书分工、材料七类）。

## 何时使用

- 用户丢通知链接或 PDF，问「怎么报、要什么材料、时间节点」
- 要整理成 Word，并附申报系统链接
- 先投后股 / 先补后股 / 开放课题 / 成果转化专项等**流程梳理**
- 需要对照「我们能不能报」做条件初判（单独成章，标注来源）

## 硬约束

1. **以通知原文为准**：条件、截止时间、材料名称不臆造；不确定写「以系统/通知最新为准」。
2. **区分产物**：本 Skill → 步骤手册；申报书正文 → 申报书类 Skill。
3. **链接可点**：步骤后紧跟报名/系统 URL（用户提供或通知内提取）；无公开链接则明示。
4. **企业匹配分析**若需要：单独章节，标注数据来源；不把推测写成已获批。
5. **不编造文号、额度、截止日**：只能从通知/细则摘录；跨地区政策只作「结构参照」，须标明「非本次申报依据」。

## 开工前确认（缺则问）

| 项 | 说明 |
|----|------|
| 通知链接或文件 | 网页 / PDF / Word |
| 是否含「我们能不能报」初判 | 默认先问 |
| 输出文件名 | 默认 `{专项简称}-申报流程说明.docx` |
| 是否需要对照表 | 条件勾选表、材料准备进度表 |

## 常见专项类型（结构参照，以当次通知为准）

| 类型 | 典型特征 | 流程手册要特别写清的点 |
|------|----------|------------------------|
| **先补后股** | 先无偿补助，达约定条件转股权；资金可回流资金池 | 转股触发条件、持股/代持安排、未转股评估验收 |
| **先投后股** | 先以项目资金/借款等方式投入，后转股并约定退出 | 分期拨付比例、转股期限、未转股退回条款 |
| **开放课题 / 实验室课题** | 课题申报书 + 研究方案，未必含转股 | 开放单位、研究方向、结题与经费科目 |
| **成果转化 / 应用示范类** | 强调场景、知识产权与产业化指标 | 权属证明、应用证明、验收指标可量化 |

各地细则差异大（如湖北「先补后股」、长春「先投后股」、重庆高新区「先投（研）后股」）。**手册一律以用户给定的当次通知为准**；上表仅帮助 Agent 知道要抽哪些字段。

## 从通知中必须抽出的要素清单

复制此表，逐项填「通知原文定位」：

```
- [ ] 专项全称 + 主管部门
- [ ] 支持方式一句话（补/投/转股/退出）
- [ ] 申报主体资格（地域、成立年限、营收/净资产、是否可团队报）
- [ ] 产业/技术方向限制
- [ ] 知识产权与诚信要求
- [ ] 单个项目额度档次或上限、是否可重复申报
- [ ] 实施周期、转股期、分期拨付比例（若有）
- [ ] 申报材料清单（含模板附件名）
- [ ] 网上系统名称 + URL；纸件是否还要、交到哪里
- [ ] 推荐单位与推荐截止时间
- [ ] 申报截止时间（精确到时）
- [ ] 评审/尽调/公示/签约等后续环节（通知写明的才写）
- [ ] 咨询电话 / 邮箱（若有）
- [ ] 「不予受理」与诚信惩戒条款
```

## 产出文档结构（默认）

1. **项目概述**：专项名称、主管部门、支持方式一句话  
2. **模式说明**（可选）：先补/先投与转股逻辑，用通知表述，不自行发挥  
3. **申报条件**：主体、年限、财务、团队、知识产权——条目化 +「是否符合」空列（若要初判）  
4. **支持幅度与周期**：额度、拨付、起止时间填法  
5. **申报流程（分步）**：每步 = 动作说明 + **对应链接** + 责任方（申报单位/推荐单位/主管部门）  
6. **材料清单**：必备 / 可能补充；标注模板附件名；建议「电子+纸件」对照  
7. **时间节点**：发布、网上截止、推荐截止、预计评审（仅通知写明的）  
8. **注意事项与常见驳回点**  
9. **附录**：原文链接、电话、附件下载名录  

### 材料「七类」整理法（便于用户备件）

1. 申报书（封面盖章 + 正文）  
2. 主体资格（执照、章程、征信/信用、纳税等）  
3. 知识产权（专利/软著等，权属清晰）  
4. 团队证明（简历、学历职称、合同/社保）  
5. 财务审计（年报/审计报告、R&D 专项审计若要求）  
6. 诚信与保密承诺  
7. 应用佐证（检测、产学研、合同、用户证明等）  

具体以当次通知附件清单为准，可增删，但手册中须与通知名称一一对应。

### 常见全流程路径（通知有则写，无则不编造节点）

```
通知发布 → 注册完善单位信息 → 网上填报上传
→ 推荐单位审核推荐 → 形式审查 → 专家评审
→（若有）尽职调查 → 公示 → 签约拨付
→（若有）转股 / 验收 / 退出
```

## Agent 执行流程

```
1. 抓取通知全文与附件名录
2. 按「要素清单」抽取，缺项标「通知未载明」
3. 套「产出文档结构」写可执行步骤（动词开头：登录/填写/盖章/提交）
4. 如用户要「能不能报」：做条件对照表，每条写 符合/不符合/待核实 + 依据
5. 输出 Word；关键链接再点开核对一次
```

### 步骤写法示例（可模仿）

> **步骤 3｜网上提交申报书**  
> 登录「××科技计划项目管理平台」（https://…），完善单位信息后，由项目负责人按类别填写申报书，上传盖章承诺书、封面及附件。  
> **截止**：YYYY-MM-DD HH:MM（以系统关闭为准）  
> **责任方**：申报单位

## 常见驳回 / 不予受理点（写入注意事项）

| 类型 | 典型问题 |
|------|----------|
| 时效 | 逾期系统关闭；推荐函逾期 |
| 一致性 | 网上与纸件不一致；盖章缺失 |
| 资格 | 成立年限/营收/净资产不达标；已获同类支持又重复报 |
| 知识产权 | 权属不清、许可过期、与团队无共识 |
| 诚信 | 失信名单、虚假材料、同一项目换名重复报 |
| 答辩 | 要求本人答辩却无故缺席（若通知有此条） |
| 材料时效 | 检测报告、许可、用户意见超有效期（常按 2 年推定） |
