# Claude Opus 5.5 调研与实战：能力、作品示例与 Claude Code 高效用法

## 一、Opus 5.5 是什么

2026 年 9 月 22 日，Anthropic 发布 **Claude Opus 5.5**，这是 Claude 5.5 家族的第一个模型，也是 Opus 5 的直接升级版。它的核心定位可以概括为一句：**用明显更低的成本追平甚至超越此前的旗舰 Fable 5.1**。

| 项目 | 数值 |
|------|------|
| 发布时间 | 2026-09-22 |
| 上下文窗口 | 1M token，最大输出 128K |
| 定价 | 输入 $4 / 输出 $20（每百万 token），缓存读取 $0.20 |
| 思考模式 | 自适应思考默认开启，靠 `effort` 参数调节深度 |
| 终端编程基准（Terminal-Bench 4.0） | 66.4% |

相比上一代 Opus 5（$5 / $25），输入输出各降价 20%；典型负载的总成本低约 40%，输出生成快 30% 以上；缓存读取费用更是降了约 60%。

## 二、相比上一代，到底强在哪

1. **更便宜、更快**：同样的预算能跑更多任务，同样的任务能更快拿到结果。
2. **长任务 Agentic 能力更强**：默认开启"自适应思考"，思考深度由 `effort` 参数控制（默认档位从 high 调到 medium），适合交出去让它自己规划、执行、检查。
3. **写作更自然**：信息前置、少术语、更贴合用户给定的写作规则，社区普遍反馈"AI 味"明显下降。
4. **一口气读得更多**：1M 上下文 + 128K 输出，可以把整个仓库、整份文档交给它，不必再一个文件一个文件地喂。

## 三、能做什么：真实作品与示例

官方与社区在发布后密集产出了一批可复现的"作品"，大体分三类：

### 3.1 长程工程任务

- **20 万行代码审计 + 修复**：不到 3 小时完成，同一任务 Opus 5 需要 20 小时以上。
- **HAProxy 从 C 到 Rust 重写**：9.5 小时完成，几乎通过原项目全部回归测试，成本比 Fable 5.1 低约 51%。
- **68 万行代码迁移**：一天内完成。

### 3.2 创意与"vibe coding"

- **一句话生成 100 个 HTML 页面**：只要求"好看、设计不重复、自由发挥"，产出多个含完整可玩游戏的文件，且零损坏。
- **代码逐帧拍视频的"出片潮"**：模型本身不产像素，而是写 HTML/Canvas/Three.js/Remotion 逐帧绘制、FFmpeg 合成，再调用 Seedance、Midjourney、ElevenLabs 等专业模型出图出音。代表作品如翻拍 MV《Claude Pop》（约 320 万播放）、反乌托邦微电影（马斯克转发并评价"已经是 AGI 的 80%–90%"）。
- **浏览器开放世界游戏 Wildbrush**：最多 6 个 Agent 并行、边玩边改，做出带四种笔刷武器、两个生物群系、三个解谜地牢和巨型 Boss 的可玩游戏。
- **一条提示词从逻辑门手搓出一台计算机**：连续跑了约 30 小时。
- **RTX 加速路径追踪器**：约 1 小时从单条提示词生成 C++/CUDA 代码。
- **1113 块真实乐高件设计 Microduck**：校验 3204 处连接、碰撞与重心，产出 141 页 / 237 步的说明书、零件清单与演示视频。

### 3.3 知识与教育

- **研究报告质量**：官方测试中 18 份报告有 16 份通过质量线（无编造数字或引用），此前的 Opus 5 与 Fable 5.1 均未通过。
- **音乐**：生成巴洛克风格双簧管协奏曲（盲测中 60% 听众认为是人类作品）；歌词由 Opus 5.5 完成的 CUDA 教学歌《Chasing the Roofline》等。

## 四、怎么用好：Claude Code 实战

光有强模型还不够，用对方法才能把长任务优势发挥出来。下面几条直接来自官方使用手册与企业实践。

### 4.1 需求要可检查

不要写"帮我升级一下"，而是把任务拆成三个要素：**做什么、做到什么程度算完成、什么情况停下问你**。例如：

> 把短信发送功能迁移到新版 SDK。完成标准：1) 所有发送入口改用新 API；2) 清理旧依赖；3) 单测与集成测试全通过；4) 若新版本无法兼容现有业务，先说明差异等我决定。

"完成"必须是可验证的，而不是一句"做好"。

### 4.2 任务要可持续：写清何时继续、何时停下

把工作规矩写进 `CLAUDE.md`，关键是把"该继续"和"该停下"一起讲清楚：

- 范围内还有能推进的工作就继续做，汇报进度时也接着做下一步，不必每次等我确认；
- 确实缺我的决定或资料、无法推进时才停下说明缺什么；
- 删除数据、强推代码、改仓库外内容前，先征求确认。

### 4.3 结果要可验证：汇报先看"待你处理"

约定每次任务结束按三部分汇报，并让 AI 先自查一遍代码变更：

> 对照 main 分支审查当前分支改动，只列出必须修复后才能合并的问题，写清文件名、行号、什么情况出错、原因与复现方式。

"这段可能有问题"不算线索，要有能继续追下去的具体位置。

### 4.4 提示词做减法：删掉"仔细思考"

Opus 5.5 默认就会先思考，"请仔细思考、一步一步来、请认真分析"这类叮嘱既无效又拖慢响应，应一并清理。想让复杂问题多想一想，用 `effort` 设置调节即可；想快，直接说"直接回答"。

### 4.5 长任务用 TASKS.md 保进度

在项目根目录放一个 `TASKS.md`，让模型把待办写入、完成即更新、遇到阻塞即补充。这样即使对话上下文被压缩，进度也不丢失。常用斜杠命令速查：

| 命令 | 作用 |
|------|------|
| `/fast` | 快速模式（同一个模型，速度快但费用更高） |
| `/model` | 切换模型 |
| `/config` | 打开配置（自动切换模型等偏好） |
| `/clear` | 清空当前对话上下文 |

## 五、竞品定位与选型建议

Opus 5.5 的直接对手是 OpenAI 的 GPT-6 Astra、Google 的 Gemini 3.0 Pro，以及 Anthropic 自家的 Fable 5.1。一个实用的选型口径：

- **日常企业开发、代码迁移、大型重构**：首选 Opus 5.5——性价比最高，长任务稳定性最好。
- **科研攻关、超高难度推理**：Fable 5.1——绝对能力最强，但价格接近 Opus 5.5 的两倍，日常开发不划算。
- **超长文档 / 强多模态**：Gemini 3.0 Pro——上下文和多模态是优势，但复杂自主任务偏弱。
- 需要说明的是：到了这个能力层级，各家基准分数差距已经很小，官方也提醒"高分边际不如看起来那么可靠"，实际选型应以自己在真实任务上的对比为准。

## 六、局限与注意

- **未必交付你最急着要的东西**：第三方实测中，让它十分钟写一份按分钟安排的培训日程，它花了近五分钟思考、做了训练数据和材料，但最核心的日程表却没交出来。
- **"看起来完成"≠"真能用"**：乐高手册出现过浮空件；号称复刻全套 Adobe 的项目，其自身文档也承认与真实软件的等价性远不足 50%。
- **验证仍要人兜底**：多 Agent 汇报"没问题"不代表真没问题，每个结论都要能落到文件、行号和依据上。
- 上下文与定价信息请以官方文档为准，本文数据核对于 2026-10-16。

## 七、总结

Opus 5.5 最大的价值不在某一条基准，而在**长程、多步骤任务里的自主推进能力**：给一个开放的总目标，它能自己规划、拆解、执行、检查，把创意一直到成品串起来。与此同时，它的局限也很诚实——优先级判断、结果可验证性仍要人来把关。用好它的关键，是把需求写清楚、把"完成"定义成可检查的标准、把进度和汇报约定好。
