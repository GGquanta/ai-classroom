
# 用 AI Skill 把产品材料变成销售宣讲话术

## 写在前面

销售对外宣讲时，手里往往只有一叠宣讲 PPT、产品白皮书或项目材料。技术同事写得细，销售却未必能「照着讲完、讲圆」——要么信息过深讲不动，要么一被追问就越界到报价、工艺、部署细节。

用 Agent Skill（或等价的固定 Prompt 流程）可以把这件事做成可复用流水线：**吃透材料 → 定信息水位 → 写成连贯口播文 → 加上使用要求 → 输出培训用 Word**。目标不是替销售背技术，而是产出一份「能讲、敢讲、知道边界」的对外话术。

![从产品材料到可照着讲的话术：AI 协助整理与交付](/assets/sales-pitch-script-skill/cover-hero.png)

本文面向需要做销售培训稿、对外讲稿的同事，也适合把同类任务沉淀为团队 Skill。文中示例为方法说明，不涉及具体公司机密。

---

## 一、何时使用

适合在下列场景调用本流程（或对应 Skill）：

- 基于 PPT / PDF / 产品材料写**对外宣讲话术**、销售培训稿
- 技术材料过细，需要压成**可口播、可培训**的文章版
- 希望销售讲清方向与亮点，同时**统一「追问时如何转接」**的口径

不太适合：

- 内部核心技术培训（需要完整原理与实现路径）
- 商务报价、合同条款、涉密项目实施方案

一句话区分：**对外能讲清楚「我们是谁、解决什么、凭什么」即可；更深内容留给技术对接。**

---

## 二、核心原则：展示三分，藏三分

对外话术的成败，往往不在文笔，而在**信息水位**——写多了像泄密，写少了像空话。建议按下表筛选。

![信息水位示意：可对外展示与必须藏起的边界](/assets/sales-pitch-script-skill/info-waterline.png)

| 可以写 | 不要写 |
| --- | --- |
| 公司定位、业务方向、适用场景 | 详细设计、核心工艺、部署图纸 |
| 原理点到为止（一句话说明「靠什么」） | 原理推导、算法细节、实现路径 |
| 关键指标（体积、速率、灵敏度等招牌数字） | 完整参数表、测试条件、友商细比 |
| 亮点（首创、抗攻击、项目背书） | 报价、商务条款、内部组织细节 |
| 标杆项目点名与方向 | 涉密项目细节、可复现的实施方案 |

实践中可记三条口诀：

1. **方向可见、路径不可见**：可以说「靠什么思路」，不说「怎么做出来」。
2. **招牌数字可留、参数表不留**：只保留对外已公开或已授权的关键指标。
3. **追问有统一出口**：凡超出水位的问题，一律转技术同事对接，避免现场即兴发挥。

## 三、五步工作流

![五步工作流：吃透材料 → 定水位 → 口播文 → 使用要求 → Word 交付](/assets/sales-pitch-script-skill/five-step-workflow.png)

### 1. 吃透材料

从 PPT / PDF / 产品文档中提取结构与要点，建议按四块归类：

- **业务**：定位、政策或行业背景、解决的问题
- **产品**：产品线、场景、一句话原理、关键指标、亮点
- **项目**：标杆客户/级别与方向（细节标注「另行介绍」）
- **资质与团队**：专利/认证/奖项数字；创始人、科学家各一两句

材料不全时先列「待补清单」，不要用模型臆造指标或项目背书。

### 2. 定信息水位

按上一节对照表做减法：保留方向、一句话原理、关键指标、亮点；删除设计细节、报价、图纸、完整参数与可复现方案。

### 3. 写成连贯文章

合成**一整篇可照着念的口播文**，按自然段推进，不要「第 N 页」式标题。默认结构见下一节。

### 4. 加上文首使用要求

文首写入固定「使用要求」（模板见下文），让培训现场口径一致。

### 5. 输出 Word

交付培训用 Word：微软雅黑、标题居中、正文首行缩进、1.5 倍行距；同时可保留 `.md` 源稿便于改稿。

| 文件 | 说明 |
| --- | --- |
| `*-对外宣讲话术（培训用）_文章版.docx` | 主交付，给销售 |
| 同名 `.md` | 可选，便于协作改稿 |

---

## 四、默认文章结构

按下列顺序组织成若干自然段：

1. **开场**：公司全称、一句话定位、本次讲什么
2. **背景**：政策/行业需求 → 我们解决什么
3. **业务与产品总览**：底座能力 + 几条产品线
4. **分产品**：每条线一段——场景 → 一句话原理 → 关键指标 → 亮点 → 适用边界
5. **标杆项目**：点名客户/级别与方向，细节「另行介绍」
6. **资质与团队**：专利/认证/奖项数字；关键人物各一两句
7. **收尾**：地址 + 引导客户选方向 + 转对口对接

### 原理 / 指标 / 亮点写法

- **原理**：一句即可，例如「利用真空能量涨落生成真随机数」「捕捉极微弱光子信号」。
- **指标**：只留对外招牌数，例如体积约 0.7 cm³、速率 10Gbps 以上、检出限 0.1–1 ppb。
- **亮点**：首创、抗侧信道、芯片化可集成、已中标国家/省级项目等。

写法自检：读完一段，销售是否说得出「场景—靠什么—多好—为何可信」四件事，且不会被追问拖进实现细节。

---

## 五、文首「使用要求」模板

文首必须包含（可按公司名微调）：

> 本话术供对外宣讲培训使用。使用要求如下：
>
> 一、可按本文连贯讲述，讲清原理方向、关键指标和亮点，不自行扩展更深技术细节和实施方案。
>
> 二、客户追问详细设计、报价、部署图纸、核心工艺时，统一回复：「这个我们安排技术同事单独对接。」
>
> 三、本话术用于对外介绍，不作为内部核心技术培训材料。

这三句话既是给销售的「护栏」，也是给 Skill 的硬约束：生成稿若缺少文首要求，应视为未完成交付。

## 六、在 Cursor 中落地为 Skill（简要）

若希望团队一键复用，可把上述原则与模板沉淀为 Cursor Skill（`SKILL.md`），建议至少写清：

| 区块 | 写什么 |
| --- | --- |
| 触发场景 | 用户要基于 PPT/PDF 写宣讲话术、销售培训稿时启用 |
| 信息水位表 | 「可以写 / 不要写」对照，禁止臆造指标与涉密细节 |
| 输出结构 | 开场→背景→总览→分产品→项目→资质→收尾 |
| 文首模板 | 使用要求三段，原样或按公司名微调 |
| 交付格式 | Word 排版约定 + 可选 Markdown 源稿 |

调用时把原始 PPT/PDF（或导出文本）与「受众是销售培训」一并交给 Agent，并要求先列出信息水位筛选结果，再生成全文——比直接「帮我写讲稿」更稳。

## 七、顺带一提：AI 相关的高效办公方法

把「材料 → 可交付文稿」做成 Skill，只是 AI 办公的一种形态。下面几条投入小、复利高，适合和销售话术流程一起用。

![AI 高效办公常见场景：纪要、邮件、材料转话术、知识沉淀](/assets/sales-pitch-script-skill/ai-office-efficiency.png)

### 1. 固定模板，而不是每次从零提问

会议纪要、周报、对外话术、邮件润色，各自维护一份「输入—结构—禁区—交付格式」。Agent 越清楚边界，返工越少。话术 Skill 本质就是这类模板的加强版。

### 2. 先结构化，再润色

常见顺序：**提取要点 → 定取舍 → 成稿 → 润色排版**。跳过前两步直接润色，容易把不该对外的细节写得很漂亮。

### 3. 多模态吃材料，人工守事实

PPT 截图、扫描件、录音转写都可以丢给支持视觉/长文档的模型做初提；**指标、项目名称、资质数字必须人工核对**。AI 负责速度，人对齐事实与合规。

### 4. 一种内容，多种出口

同一套产品要点，可裁成：对外口播稿、一页纸简介、展会电梯演讲（90 秒）、FAQ 口径卡。先维护「信息水位后的主稿」，再按场景裁剪，避免多头维护互相矛盾。

### 5. 把成功案例沉成 Skill / 规则

某次做得好的话术结构、某类客户的开场方式，写入 Skill 或项目 Rules，下次直接调用。个人效率会变成团队效率。

## 八、质量自检清单

交付前快速过一遍：

- [ ] 文首「使用要求」三节齐全
- [ ] 无报价、无部署图纸、无核心工艺与可复现方案
- [ ] 原理均为一句话，无推导与实现路径
- [ ] 指标仅为对外招牌数，来源可核对
- [ ] 分产品段落覆盖：场景 → 原理 → 指标 → 亮点 → 边界
- [ ] 标杆项目只点名方向，细节标注另行介绍
- [ ] 全文可连贯口播，无「第 N 页」式跳转
- [ ] Word 排版符合培训发放习惯（或已附 `.md` 源稿）

---

## 九、一句话总结

**定水位、写口播、加护栏、再交付**——让销售讲清方向与亮点，把深度问题留给技术对接；把流程写成 Skill，并搭配「模板化 + 先结构后润色 + 人工守事实」的 AI 办公习惯，同类材料就能稳定复用。
